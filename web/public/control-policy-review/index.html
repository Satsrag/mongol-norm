Control-character removal policy

A complete-round plan combining the existing ZWJ rules and the proposed ZWNJ single-pass rules.

2026-11-02Source snapshot 1c672bc16 ordered control pairs

Status: ZWJ drop is implemented. The unified outer loop, ZWNJ drop, and repeated-MVS merging described here are planned behavior; the live playground continues to use the current engine.

01Processing pipeline

01.1

Run unified post-processing on parsed written units after pre-shape and before duplicate unification. FVS is already attached to its letter at this stage.

For positioned-unit input, first validate the original inventory and positions, then expand required implicit ZWJs and use the same post-processing. Preserve validation order and the existing error contract.

01.2
pre-shape written units
repeat one complete round:
  1. Merge consecutive identical ZWJ, ZWNJ, MVS units
  2. Run the existing complete ZWJ drop helper
     (it reaches its own ZWJ fixed point)
  3. Run one left-to-right ZWNJ drop scan
  Repeat from step 1 only if this complete round changed the sequence
After stability:
  Run duplicate unification once (e.g. final I+Aa → G)
  Encode the stable canonical shape → norm

Step 1 only merges identical runs; step 2 only removes ZWJ; step 3 only removes ZWNJ. Keep Nirugu count and order throughout. Both removal passes use the current, already updated sequence.

The existing ZWJ helper retains its own repeat-merging safeguard and internal fixed-point loop. Calling the complete helper preserves current behavior; a single ZWNJ scan does not revisit an earlier kept break until the next outer round.

Every changing round strictly reduces the number of control units; no step inserts controls. With a finite input the outer loop terminates. An unchanged complete round is the stopping condition.

01.3

ZWNJ: one scan, one simulated removal at a time

  • Take the output of step 2. Scan ZWNJs from left to right; keep a ZWNJ only when it is the entire current sequence [Zwnj], or when removal fails the checks below.
  • If immediately adjacent to MVS, remove ZWNJ: MVS still supplies the break. Adjacency means the immediate unit, without skipping over Nirugu or ZWJ.
  • Otherwise record current letter positions, simulate removal of only this ZWNJ, and recompute positions. ZWJ and Nirugu remain in the sequence and contribute their connections.
  • Remove only if every affected letter keeps its position or passes an approved equivalence for that letter and position pair. A missing equivalence means keep the ZWNJ.
  • After removal, keep the index in place; after keeping, advance it. Continue with the updated sequence until the end of the pass.

Leading and trailing breaks have no letter-position change and can be removed, except for the single-unit case. For two letters, test both sides; beside a joiner, test the affected letter while preserving the joiner.

01.4

Encoding and read-back

After control processing and duplicate unification, split the canonical shape at the remaining ZWNJs. Encode each segment independently, verify each segment against its target, reinsert ZWNJs, and verify the complete word. A failed segment invalidates the whole candidate.

Reuse the current chachlag Aa strategy: try bare a for the whole target first, then the existing a+FVS2 spelling (1820 180C) when needed to preserve the complete target. Do not choose encodings from the original input context. Keep MVS suffix and chachlag cases distinct.

A segment may encode Aa differently from standalone norm while preserving the same target units. Standalone Mvs+Aa, Nirugu+Mvs+Aa, and ordinary representable chachlag continue to prefer bare a. Preserve existing whole-word strict, lenient, and unit-API failure behavior.

02Control rules

02.1

ZWJ

Step 2 calls the complete existing drop_redundant_zwj(). At an edge, remove only if the letter belongs to the applicable table. A boundary is the sequence start/end, MVS, or ZWNJ; an adjacent Nirugu or ZWJ counts as a connection on the far side.

02.2

Nirugu

ZWJ and Nirugu both count as joiners through is_joiner(), but remain distinct units: U+200D and U+180A. Never merge or remove Nirugu in this policy; preserve its count, order, and visible strokes.

Step 2 removes ZWJ from Zwj+Nirugu or Nirugu+Zwj. Step 3 may remove an adjacent ZWNJ only after the position checks. Nirugu+Nirugu preserves both units.

02.3

MVS

The proposed step 1 merges each consecutive MVS run into one, including chachlag Aa after J/W. The reviewed N-dot difference is accepted as equivalent: …N+Mvs+Mvs+Aa → …N+Mvs+Aa. Preserve the order and segment boundaries of the surviving MVS units.

The ZWNJ scan itself never merges MVS. Mvs+Zwnj+Mvs becomes Mvs+Mvs in step 3, and becomes Mvs in step 1 of the next round. Reuse the existing encoding strategy and validate the actual result.

02.4

Repeated controls, edges, and control-only inputs

Merge identical consecutive ZWJ, ZWNJ, and MVS runs before removal. The singleton exceptions [Zwj] and [Zwnj] apply only when the entire current sequence has length one, not whenever a word contains just one control. Empty input stays empty.

Use the same fixed order for mixed control-only input: Zwj+Zwnj+Zwj → Zwnj; Zwj+Zwnj → Zwnj; Nirugu+Zwnj+Nirugu → Nirugu+Nirugu. No separate shortcut bypasses the three steps.

03Shared equivalence

03.1

Compute positions from the current written-unit chain with the encoder’s slot_position() and is_joiner() rules: ZWJ/Nirugu connect; MVS/ZWNJ break the chain. A letter unit is any written unit other than these four structural controls.

ZWJ removal moves joined forms toward edge forms; ZWNJ removal may make the reverse transition. Query the same reviewed per-letter equivalence, using each letter’s actual outer context. For two letters around ZWNJ, both checks must pass.

03.2

Reuse the four reviewed tables (57 entries in total) and explicitly confirmed per-letter paths, including isol ↔ medi only when an approved path exists for that same unit. A missing encoding, an unreviewed pair, or a decision for another unit is not evidence of equivalence.

Preserve the source and missing-encoding status of each reviewed decision when exporting shared rule data. Keep existing ZWJ decisions where evidence is missing; keep ZWNJ whenever its removal requires an unconfirmed equivalence. The linked detail pages show the published snapshot and actual norm comparisons.

Control processing is a pure unit transformation. Run encoding afterwards; use a pinned Hudum font and HarfBuzz comparisons as offline validation rather than a runtime dependency.

04Implementation sequence

04.1

Keep the existing ZWJ behavior and encoding regression cases as the baseline. Extract shared reviewed equivalences and position helpers without changing their meaning.

04.2

Implement identical-run merging and the ZWNJ scan in the Rust core. Connect the complete-round loop in src/shaper.rs canonical_units(), before the single src/duplicates.rs collapse() call, then reuse the existing shape → norm encoding pipeline.

04.3

Both shaping backends and the Python, CLI, and browser entry points must share this one core policy. After acceptance, update the canonical-policy version, affected golden data, and stored-key migration notes, and revise relevant open issues or PRs in English as part of that implementation.

Publishing this plan and its two reference pages does not activate ZWNJ drop, MVS-run merging, or the outer control loop in the library or playground engine.

05Acceptance and sources

05.1
  • Keep existing reviewed ZWJ cases passing; change only golden outputs affected by accepted new control rules.
  • Verify A+O+Zwnj+O+A → A+O+O+A, and keep ZWNJ in A+N+Zwnj+A+A. Check both letters, not just one side.
  • Cover all grouped ZWNJ rules: leading/trailing breaks, repeated ZWNJ, singleton controls, and adjacent ZWJ, Nirugu, or MVS. Keep Nirugu count and order.
  • Cover all 16 ordered control pairs, with control-only inputs and with letters on both sides. Include combinations of three or more controls.
  • Distinguish the single-scan output N+Zwnj+B+I from the stable control result N+B+I for N+Zwnj+B+Zwnj+I. Check that a no-change round stops the loop.
  • Verify Mvs+Zwnj+Mvs → Mvs+Mvs in step 3, then Mvs in the next step 1; accept the reviewed N-dot equivalence when merging MVS.
  • Cover J/W chachlag Aa after repeated MVS and A+J+Mvs+Mvs+Zwnj+Aa; removal of redundant controls must leave an encodable target.
  • Cover A+J/W+Mvs+Aa and A+J/W+Zwnj+Mvs+Aa, while preserving the required break in A+J/W+Zwnj+Nirugu+Mvs+Aa. Verify segments independently and the rejoined word.
  • Prefer bare a for standalone Mvs+Aa, Nirugu+Mvs+Aa, and ordinary chachlag when possible. Test necessary FVS2 fallback and record actual narrow/wide MVS gaps.
  • Verify termination and idempotence of the complete post-processing, convergence of reviewed equivalent inputs, unique canonical text for the same canonical shape, and existing whole-word failure contracts.
  • Compare canonical units from both shaping backends and encoding results across Rust, Python, CLI, and browser entry points.
  • Validate positioned-unit input before expanding implicit ZWJ; compare with the expanded written-unit API. Keep raw shaping rules and raw-unit corpus semantics.
  • Render actual norm text with HarfBuzz and a pinned complete Hudum font. Retain before/after text and code points, and use the reviewed equivalence decisions.
